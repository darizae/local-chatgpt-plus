# VPS repository development friction audit

Scope: live Aruba MCP connector, 2026-11-24. Read-only inspection of effective permissions, tools, service metadata and safe capability probes. No production service restart, permission bypass, secret inspection, paid model run or remote publication was performed.

| Area | Verified current behavior | Development impact | Remediation |
|---|---|---|---|
| Native SAIA jobs | Installed launcher defaults to 90 s / $0.05, queue imposes four model submissions per rolling day; no pending jobs at inspection. | Routine delegation rejected despite idle worker; generic error. | Delete rolling quotas; new $1 / 15 min defaults, $5 / 30 min configurable maxima. Install new broker/launcher and update live profile once with authorized administrator. |
| Self-deployment | Root-owned host install directories not writable; MCP `NoNewPrivileges=yes`, no capabilities, maintenance socket inactive. | Cannot reload its own service or replace privileged helper. | One-time reviewed host bootstrap; future ordinary app restart via fixed maintenance operation. |
| npm/pnpm/pip/uv | Node, npm, Python, pip and uv available; default home npm and uv cache directories and pnpm store read-only; pip cache disabled; pnpm/corepack not found on PATH. | Fresh package installs, pnpm builds and Python dependency resolution may fail or run without cache. | New workspace-local cache environment in migration; verify fresh install and pinned pnpm tooling. |
| Git | Git push broker status OK; 10 pre-registered repository names, origin-only checked-out feature branch, clean checkout, secret scan; main/master/develop/release etc. protected. SSH key directories inaccessible to MCP. Git author identity absent in audited checkout before local commit override. | New repo push/onboarding, private fetch, force/tag/release flows, commits without identity may fail. | Scoped registration, identity setup and PR workflows; avoid publishing unless requested. |
| Docker | Docker CLI installed, `docker info` denied by daemon socket ACL; agent not in docker group. | Compose/database/integration tests requiring Docker cannot run through existing socket. | Rootless or separately isolated container service. Rootful Docker access is equivalent to broad host privileges. |
| Browser/UI | Chromium/Chrome and Playwright executables not found on MCP PATH; PTY, REPL, computer-use and mutating/unknown upstream MCP tools disabled by current custom profile. | Interactive installers, browser E2E and upstream deployment tools can be blocked. | Scoped browser/test runtime, cached browser install, explicit capability routes for routine development. |
| Commands and paths | Application profile permits writes and shell commands under /home/agent/workspaces/projects; regexes deny sudo, destructive Git operations, recursive forced deletion, killall/pkill, host power/disk commands. Regex matching uses entire command text. | False positives in command arguments and routine local cleanup; file tools cannot access outside workspace roots. | Structured workspace-scoped cleanup/process control and better diagnostics; retain host-level boundaries. |
| Runtime resources | MCP: 640 MiB cgroup memory, 1 CPU quota, 128 tasks; model queue: 1.5 GiB, 1 CPU quota, 128 tasks. Host ~3.8 GiB RAM, ~23 GiB free disk at inspection. | Big JS monorepo builds, parallel tests, model tools and browser runs may hit cgroup limits even with host memory free. | Instrument peak usage and tune by workload; avoid unnecessary parallel heavy builds. |
| Long tasks | Native run_command permits up to 3600 s; process tools exist, but MCP-owned jobs can be interrupted by a backend restart. Native subagent queue is serial, launcher parent timeout and prompt/result limits still apply. | Long-running builds can lose transport/session state; repeated independent agents wait. | Durable job execution, receipt-based resume, queue/result recovery. |

The local Git wrapper handles push differently from fetch, and direct private fetch/clone was not tested here. No destructive commands, actual pushes, container startup or paid model calls were used as probes. Not all listed restrictions are defects: the point is to make routine development work through supported, narrow interfaces rather than requiring human intervention each time.
